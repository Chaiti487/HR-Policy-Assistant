# Company HR Policy Assistant

An AI-powered HR Policy Assistant that allows employees to ask questions about company HR policies and receive grounded answers with policy source citations.

The application uses a **Retrieval-Augmented Generation (RAG)** architecture. Relevant information is retrieved from uploaded HR policy documents before generating an answer using Google Gemini.

The project uses **LangChain** for LLM integration, **Gemini Embeddings** for semantic search, and **ChromaDB** as the vector database.

---

## Overview

The application provides two separate portals.

### Employee Portal

Employees can:

* Ask questions about company HR policies
* Receive answers based only on available policy documents
* View the document and section used as the source
* Ask overview or summary questions
* View a demo video explaining the application workflow
* Receive a safe refusal when the requested information is not available

### Admin Portal

Administrators can:

* Log in to the admin portal
* Upload HR policy documents
* Process and index uploaded documents
* View currently indexed documents
* Delete policy documents
* Make policy information available for employee queries

For this assignment, the system uses a single company HR policy knowledge base.

## Key Features

### 1. Policy Document Upload

Administrators can upload HR policy documents through the Admin Portal.

Currently supported formats:

* `.txt`
* `.md`

The uploaded document is:

1. Validated
2. Parsed
3. Divided into sections
4. Split into smaller chunks
5. Converted into embeddings
6. Stored in persistent ChromaDB

Each chunk stores metadata such as:

* Document name
* Section name
* Chunk index

---

### 2. Semantic Search

When an employee asks a question, the question is converted into an embedding using Google's `gemini-embedding-001` model.

The system performs semantic similarity search against the policy embeddings stored in ChromaDB.

For normal factual questions, the system retrieves the **top 2 relevant policy chunks**.

A relevance threshold is applied before sending the retrieved information to Gemini. This helps prevent clearly unrelated policy information from being used to answer a question.

For example:

> How many casual leave days can I carry forward?

can retrieve information related to:

> A maximum of 8 unused casual leave days can be carried forward to the following year.

---

### 3. Grounded AI Answers

The retrieved policy chunks are provided to Gemini as context.

The application uses **LangChain's `ChatGoogleGenerativeAI`** integration to communicate with the Gemini language model.

The model is instructed to:

* Use only the provided HR policy context
* Not use outside knowledge
* Answer factual questions only when the required information is available
* Summarize relevant information for overview questions
* Refuse when the policy does not contain the requested information

If the available policy information is insufficient, the system returns:

> The HR policy does not provide this information. Please contact HR.

---

### 4. Overview Questions

The system handles overview and summary questions separately.

For example:

> What are the main types of leave available?

> What are the main IT security policies?

For normal factual questions, the system retrieves the top 2 relevant chunks. However, overview questions may require information from multiple sections.

Therefore, the system identifies overview-style questions and retrieves **all chunks from the relevant policy document**.

Gemini then uses these chunks to generate a more complete summary while remaining grounded in the policy.

---

### 5. Policy Citations

The backend generates citations using metadata stored with the ChromaDB chunks.

Citations are not generated by Gemini.

For normal questions, the most relevant policy section is returned.

For overview questions, multiple policy sections can be returned.

Example:

```json
{
  "question": "How many casual leave days can be carried forward?",
  "answer": "A maximum of 8 days of unused casual leave may be carried forward to the next calendar year.",
  "citations": [
    {
      "document": "leave-policy.md",
      "section": "4.1 Casual leave carry-forward"
    }
  ]
}
```

---

### 6. Safe Refusal

The system is designed to avoid hallucinating company policy information.

If the available policy does not contain the required information, the assistant refuses to answer.

Example:

```json
{
  "question": "Can I get a salary advance?",
  "answer": "The HR policy does not provide this information. Please contact HR.",
  "citations": []
}
```

Citations are not returned when the system refuses to answer.

### 7. Demo Video

The Employee Portal includes a demo video that demonstrates the main application workflow, including:

* Asking HR policy questions
* Receiving grounded answers
* Viewing policy source citations
* Handling unsupported questions
* Using the Admin Portal to upload policy documents

The demo video is provided through YouTube and can be accessed directly from the Employee Portal.

## RAG Pipeline

The application follows this pipeline:

```text
HR Policy Documents
        |
        v
Document Parsing
        |
        v
Section Splitting
        |
        v
Text Chunking
        |
        v
Gemini Embeddings
        |
        v
ChromaDB
        |
        |
Employee Question
        |
        v
Gemini Query Embedding
        |
        v
Semantic Search
        |
        v
Relevant Policy Chunks
        |
        v
Relevance Check
        |
        v
LangChain + Gemini
        |
        v
Grounded Answer
        |
        v
Citations
```

For overview questions, the relevant document's chunks are retrieved before generating the summary.

## Grounding Strategy

The application uses multiple mechanisms to reduce hallucinations:

1. Semantic retrieval from the HR policy knowledge base
2. Top-2 retrieval for normal factual questions
3. Relevance threshold checking
4. Restricted policy context provided to Gemini
5. Explicit instruction not to use outside knowledge
6. Special handling for overview questions
7. Safe refusal when information is unavailable
8. Metadata-based citations
9. No citations for refused answers

## LangChain Usage

LangChain is used for the LLM integration layer.

The project uses:

```python
from langchain_google_genai import ChatGoogleGenerativeAI
```

LangChain provides the interface for communicating with Gemini and generating the final response from the retrieved policy context.

The application maintains control over the custom parts of the RAG pipeline, including:

* Document processing
* Chunking
* Embedding generation
* ChromaDB retrieval
* Relevance checking
* Overview handling
* Citation generation
* Safe refusal logic

## Configuration

Create a `.env` file inside the `backend` directory:

```text
GEMINI_API_KEY=your_api_key_here
```

The API key should never be committed to GitHub.

The `.env` file is excluded using `.gitignore`.

## Running Locally

### 1. Clone the repository

```bash
git clone https://github.com/Chaiti487/HR-Policy-Assistant.git
cd HR-Policy-Assistant
```

### 2. Create a virtual environment

```bash
python -m venv .venv
```

### 3. Activate the virtual environment

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

### 4. Install dependencies

```bash
pip install -r backend/requirements.txt
```

### 5. Configure Gemini API key

Create:

```text
backend/.env
```

and add:

```text
GEMINI_API_KEY=your_api_key_here
```

### 6. Start the backend

```powershell
cd backend
uvicorn main:app --reload
```

The backend will be available at:

```text
http://127.0.0.1:8000
```

### 7. Open the frontend

Open the frontend files through a local server or the configured frontend deployment.

## Limitations

This project is an assignment-level prototype.

Current limitations include:

* Only `.txt` and `.md` files are supported
* Admin authentication is basic
* ChromaDB is used as a local vector store
* No document versioning
* No advanced reranking
* Citation granularity is currently document and section based
* Production-level authentication and authorization are not implemented
